LinkRadar

LinkRadar is a single-machine, multicore graph analysis project that computes all-source betweenness centrality for unweighted, undirected networks using Brandes’ algorithm. It combines CSR, Numba, tree quotient graphs, and multithreading, and supports checkpoint recovery and interactive visualization.

Type: Course Project

Team: Yuxiang Liu

GitHub: https://github.com/lyx0902/LinkRadar

Project details

Key Node Identification and Parallel Computing for Large Networks

Tech stack: Python, NumPy, Numba, NetworkX, Multiprocessing, HTML/CSS/JavaScript

Exact graph algorithms and data processing

Implemented all-source Brandes betweenness centrality for unweighted, undirected networks, using BFS for shortest distances and equal-length path counts followed by reverse dependency accumulation. Built edge-list cleaning, node mapping, and graph fingerprint checks for reproducible real-network analysis.

Graph compression and result recovery

Designed a peripheral-tree quotient graph that groups original sources sharing a core anchor by weight, computes weighted contributions on the core, and recovers original-node contributions using tree structure. For YouTube, this reduced traversal from 1,134,890 original sources to 470,164 core source groups.

Compiled kernels and multicore parallelism

Stored graph structure compactly in CSR arrays and used Numba to compile shortest-path search and dependency accumulation into native code that releases the GIL. Dynamically batched source groups across threads sharing the read-only core graph, with private workspaces and a final reduction.

Shortest-path edge recording

Recorded shortest-path successor edges during forward BFS and used them directly during reverse accumulation to reduce repeated adjacency scans. Across three paired trials with 64 source groups and four threads on the YouTube core, median speedup for execution and reduction was 1.436×.

Checkpointing and recovery

Implemented alternating cumulative snapshots with hash validation and atomic manifest commits to recover completed chunks. Completed the YouTube all-source task across two eight-thread sessions in approximately 2 hours 30 minutes of supervised wall-clock time, excluding the pause between sessions.

Validation and presentation

Compared all-node results against NetworkX on small graphs and two real networks. Checked large-graph results using source coverage, file hashes, and peripheral-tree formulas, and built fixed-ranking node-removal experiments and an interactive dashboard showing connectivity under betweenness, degree, and random strategies.

AchievementAnalysis

Overall project: Integrates Steam data from multiple sources to analyze game trends, clustering, reviews, and player engagement, providing explainable recommendations and interactive presentations.

My contribution: Implemented automated achievement classification and mainline progression analysis, interpreted player engagement using gameplay, playtime, and reviews, and visualized the data.

Type: Course Project

Team: Wenhai Wang, Yuxiang Liu, Jinhui Yang, Meitian Ye, Zhengyu Zhu

GitHub: https://github.com/WwhdsOne/achievement-analytics

Project details

Mainline Progression and Player Engagement Analysis from Steam Achievements

Achievement semantic labeling pipeline

Built a DeepSeek-based multilabel classification pipeline using structured inputs of game names, genres, and original achievement text, covering eight categories including mainline, side quests, collection, and challenges. Validated achievement ID completeness, label exclusivity, and quoted evidence, then filtered by confidence: 803 games, 48,390 achievements, and 51,854 stored labels.

Reliable calls and recoverable execution

Designed versioned prompts, request-fingerprint caching, and cached-response revalidation with request budgets, cumulative timeouts, backoff retries, and progress tracking. SQLite transactions commit per game, isolating failures and retaining low-confidence candidates and abnormal responses; committed results and valid cache enable resumption without repeating calls or rolling back the entire batch.

Mainline metrics and progression analysis

Reused the team’s existing mainline labels and ordered story nodes to calculate first, middle, and final node coverage and early, late, and full progression ratios. Addressed missing denominators, representative nodes for multiple endings, and coverage reversals. Produced a 198-game metrics table, 183 complete three-node samples, and 1,543 adjacent-node intervals to identify games with similar endpoints but different stage-level drops.

Multi-source association and uncertainty

Joined RAWG playtime, HLTB reference duration, and Steam and Metacritic ratings by AppID. Used common-sample comparisons, Spearman correlations with average ranks for ties, and 2,000 game-level paired bootstrap resamples. In a common sample of 69 games, correlations with full progression were ρ = 0.289 for absolute playtime and ρ = 0.652 for relative mainline time investment; reported confidence intervals and distinguished association from causation.

Interpretable peer baselines

Built Jaccard similarity references from complete gameplay multilabels, requiring comparable ending definitions, excluding the game itself, and enforcing a minimum peer count. Calculated median differences, interquartile ranges, and percentile positions for stage progression; provided valid primary references for 181 games and tested sensitivity to similarity thresholds, reception, and content length.

Analysis delivery and interactive visualization

Combined shared metrics and five analysis topics into 21 PNG/SVG chart sets, detailed and summary CSVs, and an interactive page. Users can select 1–5 games by AppID or Chinese or English name to inspect stage comparisons, full curves, and conditions. Offline precomputation, source fingerprint checks, and embedded HTML data keep selections limited to highlighting and details; viewing needs no database, model API, or analysis backend.

ApexLogic

A multi-agent deep research system combining multi-source retrieval and iterative review, with checkpoint-based research resumption, cross-task memory reuse, and concurrent background execution.

Type: Research Project

Team: Yuxiang Liu

GitHub: https://github.com/lyx0902/ApexLogic

Project details

A LangGraph Multi-Agent System for Open-Domain Deep Research and Question Answering

Tech stack: Python, LangGraph, Multi-Agentic Workflow, Thompson Sampling, AQD, IRCoT, PostgreSQL, Redis, Streamlit

Multi-agent orchestration and review loop

Built a Researcher → Writer → Reviewer workflow using a LangGraph state graph, persisting retrieval strategy parameters, reasoning chains, and revision records across rounds. Four-dimensional review covers factual accuracy, logical completeness, information coverage, and actionability; evidence gaps and structured revision instructions drive conditional routing through retrieval, writing, review, and further search or revision.

Coordinated retrieval strategies

Integrated DuckDuckGo, Tavily, and arXiv as heterogeneous sources. BGE-M3 vector retrieval and reranking narrow Top-20 to Top-10; reranking scores feed Thompson Sampling to allocate source quotas dynamically. AQD subquestion decomposition and IRCoT multi-hop follow-up search preserve key evidence and citations in separate ordinary and reasoning-search contexts.

Cross-task evidence memory and retrieval reuse

Built source-evidence memory on PostgreSQL / pgvector, persisting quoted excerpts, sources, expiry, and vectors. Checks evidence coverage, version, and freshness per subquestion, skipping planned searches only when conditions are met while retaining necessary evidence for writing. Redis search and vector caches support TTL expiry, concurrent request coalescing, and failure bypass.

Concurrent scheduling and recoverable execution

Designed task-level multiprocess workers and bounded retrieval-level thread pools. A PostgreSQL transactional outbox and Redis Stream consumer groups decouple page submissions from background execution; task locks, lease heartbeats, and worker concurrency management coordinate claims and external calls. Database scans compensate for lost notifications and recover disconnected tasks. LangGraph synchronous checkpoints and configuration snapshot validation enable node-level recovery while preserving committed progress.

Intent routing and report interaction

Developed an operation-recognition chain with optional Jev classification and a structured LLM fallback, confidence thresholds, target-task validation, and clarification branches, separating model decisions from execution. Supports report follow-up questions, incremental updates, rewriting, and verification; stores Q&A, sources, and report versions separately, with Streamlit views of node progress, selected retrievals, review routes, and intent audits.

Quantitative evaluation and iteration

Built a stratified HotpotQA evaluation set and compared baselines including DeepSeek-V3.2 and Qwen3-Max. Medium accuracy reached 72.0% versus 61.3% for DeepSeek-V3.2; Hard accuracy improved by over 20%. Improved handling of bad cases such as improperly permitted degraded results and parsing errors, added pytest review unit tests, and documented the work.
